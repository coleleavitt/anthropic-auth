## What's fixed

- **OpenCode 2 menu sign-in works.** Finishing an OAuth sign-in from `/claude` → Accounts failed with "Action failed" for everyone on OpenCode 2. It now stores the account. The Accounts menu explains how to connect OpenCode when the pool has no main account yet. Thanks to @colinmollenhour for the fix. (#464, #466)
- **A failed relay fallback is no longer sent twice.** When a relay request fell back to a direct send and that direct send failed after going out, the plugin could send the same request again. It now sends the direct fallback at most once, and OpenCode or Pi retries as usual.
- **Vault setup grants the approved name.** When the vault operator approved an installation under a different name than the default (for example, a second OpenCode installation), setup still granted the default name, so that installation never got access to the vault's accounts. Setup and the printed `ck auth grant` command now use the approved name. (#471)

## Changed

- **Sticky-balanced sessions wait for any short reset.** On OpenCode 1 and Pi, a session now waits on its account when whichever quota window blocks it resets within 15 minutes, including the 7-day and model limits, instead of moving and rebuilding its prompt cache. Before, only the 5-hour window held. OpenCode 2 doesn't hold yet.

To upgrade, quit OpenCode and Pi and run `npx @cortexkit/opencode-anthropic-auth setup`, or change the version in your OpenCode config.
