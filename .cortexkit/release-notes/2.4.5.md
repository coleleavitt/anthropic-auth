## Fixes

- **A weekly limit no longer parks a session for days.** In sticky-balanced routing, when the account a session was pinned to hit its weekly limit, the plugin could pass Anthropic's own retry delay to OpenCode, which then waited until the weekly reset, sometimes several days, even though other accounts had room. Now:
  - a 429 whose rate-limit headers show the limit used up moves the session to an account with room in the same request;
  - a 429 that can't be confirmed is retried after at most a minute.
  This applies to OpenCode 1 and Pi; OpenCode 2 already moved such sessions.

  A session that is already waiting for a far-off retry stays parked until you stop the turn and send it again.
- **OpenCode 2 retries on the same account in mixed sessions.** A session that also used OpenCode's own Anthropic login or an API key stopped retrying a rejected vault or local login, or a failed relay, on the same account. It retries again.

## Improvements

- **OpenCode 2 keep-warm survives a server restart.** Cache keep-warm saves its sessions, gzipped, to an owner-only folder in the system temp directory (`%TEMP%` on Windows). After a restart, sessions whose cache is still alive are warmed again, so the next turn reads the existing prompt cache instead of rebuilding it. No login data is stored, and each file is deleted when its session stops being warmed.
- `@cortexkit/common-auth` 0.31.0.

To upgrade, quit OpenCode and Pi and run `npx @cortexkit/opencode-anthropic-auth setup`, or change the version in your OpenCode config.
