## Confirmed `anthropic-auth` defects

### Pi server-fallback parity gap

OpenCode already opted eligible OAuth Fable 5/Opus 5 traffic into Anthropic's server fallback and preserved fallback boundaries. Pi did neither. A normal message start followed by thinking and terminal refusal passed through as a generic provider error.

### Unstructured refusal diagnostics

Pi mapped `refusal` to `stopReason: "error"` with human-readable text but without preserving the raw stop reason or adding Prime's machine-readable `provider_stream_failure` diagnostic. Prime's outer retry policy therefore treated the billed refusal like an unknown transient error.

### Inaccurate refusal text

The prior message claimed no output was produced and suggested a missing 1M beta. The incident contained billable thinking/output, and transport evidence proved the 1M beta was present.

### WebSocket relay cancellation hole

Direct fetch and HTTP relay propagated the request `AbortSignal`; persistent WebSocket relay did not. Cancellation could wait through connection/response timeouts or continue streaming billed work. Binary relay chunks have no request ID, so detaching an aborted request while reusing its socket would risk attributing late bytes to its successor.

## Fix

Commit `6a3d441`:

- sends `fallbacks: "default"` and `server-side-fallback-2026-07-01` for eligible OAuth Fable 5/Opus 5 requests;
- keeps custom API-key routes free of the beta, request field, and internal markers;
- stores recognized fallback model transitions as CortexKit-tagged hidden thinking markers and reconstructs the `from.model`/`to.model` boundary on the next eligible request;
- preserves both `rawStopReason` and the installed Prime compatibility spelling `stopReasonRaw`;
- emits `provider_stream_failure` with `details.kind: "refusal"`, `providerErrorType: "refusal"`, and upstream request ID when available;
- reports that input and any preceding thinking/output are billed;
- preserves a completed tool call and terminates as `toolUse` when the same response later refuses, avoiding tool replay;
- propagates cancellation through WebSocket queue, connect, retry, response, and stream phases;
- clears pending state before closing an aborted WebSocket;
- identity-fences socket message/error/close handlers so delayed events from an old socket cannot replay or corrupt a successor request.

Installed Prime code checks structured permanent failures after its first compatibility retry begins. The new diagnostic is intended to let that host classify the refusal as permanent instead of exhausting its retry budget. The pre-fix incident does not itself prove the post-fix retry count; eliminating the host’s initial compatibility retry requires a Prime Agent policy change.
